0. Run `private/tools/owner_checks.sh` (Windows deliveries/status, mirror HEAD, disks, reference pull) and `private/tools/pull_references.sh` before the first status; paste the Windows line with its check time.

   `$RA2_PYTHON` (`private/matching-pilot/20261020T123117Z/env/bin/python`); zsh noclobber is on,
   so overwrite with `>|` (a failed `>` silently skips the next command; check logs are fresh).
2. Numbers: `$RA2_PYTHON -B tools/original_target/treemap.py --json build/treemap.json`, then
   `status.py --write`. Never redirect treemap's stdout into the json; check the file is non-empty.
3. Never amend a commit a landing has seen: `land.sh` syncs the Windows mirror after each landing.
   Extra files (e.g. a rename's native rewrite) go in before the commit or in a follow-up commit.
4. A failed accept leaves state in three places: revert `manifests/original_target/index.json` and
   the touched population files, delete the new `population-N.json`, remove `population-N` from
   `private/original-target.interactive.json`, and move its `inventory/composite-<plan>` folder aside.
5. Before queueing a lane delivery behind landings that change shared headers, land it first or have
   the lane re-verify at the HEAD it will land on.
6. Post the status in the AGENTS.md "Status format" at the next landing or hand-back.

## Integration loop

0. Queue landing (2026-10-30, user via review session): every new Windows packet carries `landing.txt` (format in
   WORKER.md "Delivery": `P dir plan message`, `R spec message`, `H reason`). At each board check append the new
   packets' landing.txt lines, in freeze order, to `private/tools/landing-queue.txt` and run
   `private/tools/runq.sh private/tools/landing-queue.txt` in the background (untracked, lives in private/tools).
   It fetches missing Windows packets, lands line by line, skips a P line already fully accepted, stops on a dirty
   tree, an H line or the first failure; done lines go to landing-queue.txt.done. Touch a delivery only when the
   runner stops on it. accept_sources.bind() caches per-header work (review-session patch 2026-10-31, ~6 min -> ~25 s per
   plan; lands with the next round's commit). Object cache (review-session patch 2026-10-31, build.py): groups whose unit text, include closure, arguments and pinned compiler are unchanged reuse build/object-cache objects (RA2_OBJECT_CACHE=0 disables); verify_fresh still audits every object and whole_file_exact gates; land.sh rebuilds without the cache before refusing. Builds ~60 s instead of ~250 s. Next speed-up if needed: batch consecutive P lines into one full build.
   Packets without landing.txt are queued by hand in the same format. Never run two runners, and
   never wait on another landing with `pgrep -f` from a shell command line (it matches the waiter itself).
1. Take a delivery: frozen `d/rN/` folder with plans, drafts, header copies,
   base commit. Plans use forward-slash paths and LF endings.
2. `private/tools/land_round.sh DIR "message" PLAN...` merges DIR/shared against DIR/BASE (a header
   new at BASE that already landed is replaced only by a superset copy), reheads, accepts and lands;
   `private/tools/land_rename.sh SPEC "message"` applies a rename alone and lands. On a header
   conflict, resolve by hand and rerun with SKIP_HEADERS=1. Frozen whole-population plans carry context drafts from their base commit; when later landings
   rewrote those sources, `private/tools/rehead_plan.py PLAN` writes PLAN.head.json with unchanged
   context rows re-pointed at HEAD sources (drafts that rewrite a source are kept; missing population
   rows are added; Windows `C:/` prefixes are stripped). Accept the .head.json.
3. Merge header copies with `git merge-file src/shared/H BASE COPY` (BASE = the
   header at the worker's base commit). New headers are copied.
4. Accept each plan: `$RA2_PYTHON -B tools/original_target/accept_sources.py
   --config private/original-target.interactive.json --output
   private/original-target-20261020/accept-NAME PLAN` (accepted == candidates).
5. Land with `private/tools/land.sh "message"`: rehash, full build, commit only
   if `"whole_file_exact": true`, sync Windows, publish the GitHub snapshot,
   prune old build outputs.
6. Signature/name changes land alone through
   `tools/original_target/apply_rename.py SPEC --dry-run`, then with
   `--config private/original-target.interactive.json`, then `land.sh`.

Cadence: build after every accept (a land takes about a minute: tests, full
build, status and source index, commit, sync, publish), so a header change that
breaks another unit is isolated at once; rename batches land alone. Remote
compilation is configured by `RA2_REMOTE_COMPILE` (value in the owner's private
notes) (ssh needs the sandbox off; the user approved that for remote-compile
commands only). A worker check without `--build` can miss header impact on
other units; the full build is the gate.
